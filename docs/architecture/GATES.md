## 开始前由 2/3/5 准备

- 原型入口或安装包、安装/资源准备操作、精确版本与完整本地资源清单，明确是否存在外部调试器。
- 独立 C++ 样例：带 main，循环、函数/递归、数组、有效指针、string/vector；普通 C 样例；编译错误、可控异常和死循环样例。
- 5 号给每个断点写明确行号、进入/跳过/跳出预期位置、当前/调用者帧变量值和预期输出。不能仅检查暂停按钮变色。
- 采集模板至少包含：设备型号、iPadOS、可用空间、安装形态、应用/资源包版本、基线、兼容组合、源码/产物 hash、日期、操作人、结果与证据位置。未知信息保持空缺。

## 用户真机逐步操作单

1. 联网完成首次安装和全部资源准备，记录版本；资源未完整则结束并记录失败原因，不继续宣称离线可用。
2. 关闭应用，断开 Wi-Fi/蜂窝网络并确认无网络连接；关闭或断开辅助电脑。重新打开应用，确认资源/编辑界面均可用。
3. 粘贴 C++ 样例，临时修改一个整数和注释标记，形成此前未编译的新源码，记录源码快照/标记。提供 stdin，在 iPad 上实际编译；与预期输出比较。
4. 给用户函数内的可执行行设置断点，同时尝试空白行断点；开始调试，核对实际绑定行、暂停原因和执行位置。空白行若重定位必须显示实际位置。
5. 暂停后检查局部标量、数组元素、指针及其有效解引用、string/vector 实际内容；展开容器并修改后再观察。空/短/长字符串与空/扩容 vector 均需单独覆盖。
6. 单步进入函数、跳过调用、跳出当前函数；每次核对源码位置与值。查看递归调用栈，切换调用者帧检查对应局部变量。继续至真实输出/退出。
7. 修改源码和驱动后重编译，确认旧会话、旧暂停、旧帧数据不能覆盖新结果；调试位置对应新快照。未重编译的编辑稿应明确提示。
8. 调试状态保持暂停，等待超过普通运行时限后仍能继续；运行死循环并点击停止，确认实际计算终止、界面可用，马上重新编译/调试下一程序。
9. 换 C 样例验证输入输出、断点/单步和基础变量；换编译错误样例验证真实诊断定位；按能力集合逐项验证监视表达式及拒绝原因。
10. 使用键盘、鼠标和界面按钮操作，切换刷题 App 来回复制，测试中文和窄窗；关闭重开应用确认草稿/驱动/stdin 恢复，复制和导出内容正确。
11. 记录实际耗时、可观测内存、输出上限、后台行为与错误恢复；每项标记通过/失败/待验证并附证据。任何核心功能缺失或不能断网冷启动均不通过 G2。

## 无设备时的交付

2/3 仍交付可运行的真实原型、产物、复现步骤和桌面技术证据；5 交付样例与未填结果的验收表。1 号维持路线待定，待用户或有设备的验证者执行此操作单。不要求用户在只有状态骨架时开始测试，也不把模拟器称为 iPad 真机。

## 冻结和失败处理

G2 通过后，1 号写冻结决定：精确工具链/运行时/调试器版本、ABI、调试格式、资源与许可证、兼容项、实测能力/限制和证据。再固定 contracts 版本，扩大 UI 集成。失败时优先定位编译/符号/暂停/变量/资源/安装中的具体阻塞并换候选；不得自动降为远程方案或取消调试。
