# iPad 操作手册：首次准备、断网编译与调试

更新：2026-10-27。适用于“算法工作台”的统一离线 Web 实验入口；本轮更新步骤见 [v0.4.4说明](IPAD-UPDATE-v0.4.4.md)。

**已经提供同Wi-Fi本地HTTPS准备方案，但尚未由你的iPad确认互通，也没有完成真机验收。请先核对本轮更新说明中的固定入口和公开证书，再从第2节开始操作。** GitHub保存源码与说明，不提供本项目的在线编译服务；本手册不预填真机结果。

你在平板上只需要 Safari、系统“文件”App 和键盘/鼠标。平板不需要安装 Node.js，不需要输入终端命令。首次资源准备需要联网；断网测试阶段应关闭网络和辅助电脑。

## 1. 你现在可以先准备什么

1. 给 iPad 充电，准备好平时用的键盘、鼠标和刷题 App。
2. 打开“设置 → 通用 → 关于本机”，记下设备型号、iPadOS 版本；再查看“iPad 储存空间”，记下可用空间。
3. 在“文件”App 的“我的 iPad”里准备一个文件夹，例如“算法工作台测试”。导出的备份和测试录屏放在这里；断网时不要只依赖尚未下载到本机的云盘文件。
4. 把本手册和第 4 节代码留在平板本地，方便断网后查看。复制时保留代码里的空行，不要复制 Markdown 的三反引号。
5. 等待 1 号给出实际的 HTTPS 入口、对应版本标识，以及首次准备是否需要电脑同网的说明。

不要把电脑的 `localhost`、`127.0.0.1` 地址输入平板；它们在平板上表示平板自身。当前电脑开发地址不是平板入口。若打开地址遇到证书警告，先把提示回报给 1 号，不要自行绕过或安装来历不明的证书。

收到入口后填写：

| 项目 | 记录 |
|---|---|
| 实际 HTTPS 入口 | 以本轮更新说明为准，需平板实际确认可达 |
| 入口显示的版本 / bundleId | |
| 资源项数、总字节数 | |
| iPad 型号 / iPadOS | |
| 可用空间 | |
| 测试日期、操作人 | |

### 如果 1 号另行提供本地测试证书

使用公共受信任 HTTPS 入口时不需要此步骤。若本轮采用电脑与平板同网的本地 HTTPS，先等 1 号提供本次专用证书文件、证书名称、SHA-256 指纹和已确认的入口；不能自己猜地址。

1. 核对文件和指纹确实来自本次交付。仅安装指定的根证书配置；本次无需 VPN、代理、设备管理注册或其他管理权限。内容和说明不一致时先停止安装并回报。
2. 按系统提示安装该证书配置后，到“设置 → 通用 → 关于本机 → 证书信任设置”，只对指定测试根证书开启完整信任。手动安装证书配置不会自动获得 SSL/TLS 信任。[Apple：信任手动安装的证书配置](https://support.apple.com/en-us/102390)
3. **开启完整信任会让系统信任该根证书签发的网站证书，信任范围不限于工作台。** 这项设置需要你理解并手动决定；不能通过忽略浏览器证书警告或关闭安全检测来替代。证书私钥不应传到平板。
4. 再用 Safari 打开 1 号确认的 HTTPS 地址，仍有证书警告就回报原提示。证书信任完成也不证明校园网/访客网允许两台设备互访；以实际能否访问为准。
5. 测试结束且不再使用本地入口时，可以关闭该根证书的完整信任，并在“设置 → 通用 → VPN 与设备管理”里移除对应测试配置；只操作本次指定配置，不移除已有学校或工作配置。[Apple：分发及移除证书](https://support.apple.com/guide/deployment/depcdc9a6a3f/web)

电脑侧生成和启动细节由 1 号处理，见维护者文档 `app/offline/LOCAL-HTTPS.md`；你在平板上不用执行电脑命令。

## 2. 首次联网准备，并添加到主屏幕

以下步骤等拿到实际入口后再执行。

1. 保持 iPad 联网，用 **Safari 本身**打开给你的地址；不要停留在聊天 App 内置的小浏览器里。
2. 打开指定的固定版本“离线准备”页。页面应显示“算法工作台”、版本标识、资源项数和总大小。资源约 61 MB，准确数量以页面显示为准；下载大小不是运行内存上限。
3. 点击 **“准备离线资源”**。保持页面在前台、屏幕亮着，等待下载和逐项校验结束。期间不要锁屏、切 App 或关闭页面。
4. 看到类似 **“已检查 × 项资源，可以打开工作台”**，并且“打开工作台”可以点击，才算本轮资源准备完成。只有出现图标或进度条不算完成。若失败，保留错误提示，见第 9 节。
5. 可点击 **“申请保留网站存储”**，记下系统是否授予。系统可能拒绝；这不会自动证明离线不可用，也不会免除后面的测试。主屏 Web App 和持久化申请都不能保证数据永久存在，应导出重要草稿。[WebKit 官方存储说明](https://webkit.org/blog/14403/updates-to-storage-policy/)
6. **留在这个固定版本的离线准备页**，打开 Safari 的分享菜单，选择“添加到主屏幕”；如果系统提供“作为 Web App 打开 / Open as Web App”，将其打开，再点“添加”。不同 iPadOS 的分享菜单可能先要点“更多 / 查看更多”。[Apple：在 iPad Safari 中把网站作为 App 使用](https://support.apple.com/guide/ipad/open-as-web-app-ipad8f1f7a29/ipados)
7. 从主屏幕点击新图标，仍保持联网。核对版本与刚才一致，再点 **“检查已存资源”**。若提示尚未保存，则在这个主屏入口重新点“准备离线资源”，等完整校验通过。不要假定 Safari 页和主屏入口已经共享准备结果。
8. 从主屏入口点击 **“打开工作台”**，在工作台顶部点 **“校验本地资源”**。等待校验完成，确认“编译运行”“编译调试”已可用。
9. 若已出现自己的旧草稿，先按第 7 节导出完整草稿备份，再用测试代码替换。测试阶段只保留一个工作台窗口，避免同时编辑同一草稿。

添加到主屏幕的是固定版本的离线准备入口；不要把只含版本选择的总站首页、聊天链接或 `ui/probe.html` 工作台页当作本次主屏起点。将来拿到新版本时，先导出草稿，再按新版本说明准备，保留旧入口和备份。

## 3. 确认完全断网，再关闭重开

首次可先按第 4 节在线跑一次熟悉按钮。正式断网测试时，必须重新做下面步骤，并在断网后修改新源码。

1. 在工作台等到草稿栏显示“草稿已保存”；有重要内容时，再导出一份完整草稿。
2. 打开 App 切换器，关闭工作台。**仅回到主屏幕不算关闭重开。**
3. 打开“设置”，开启飞行模式，再进入“Wi‑Fi”确认开关已关闭；有蜂窝网络的型号再确认蜂窝数据已关闭。飞行模式下仍可能重新打开 Wi‑Fi，因此要实际检查。[Apple：飞行模式](https://support.apple.com/en-us/108785)
4. 拔掉可能联网的 USB/以太网转接器、手机共享网络线等。关闭或断开辅助电脑，记录电脑已关闭/断开；离线阶段不能让电脑提供页面或计算服务。
5. 不要只把控制中心 Wi‑Fi 图标点灰：Apple 区分控制中心的断开连接与设置中的关闭。请以“设置 → Wi‑Fi → 关闭”为准。[Apple：控制中心中的 Wi‑Fi 与蓝牙](https://support.apple.com/en-us/102412)
6. 使用蓝牙键盘/鼠标时，可以在确认 Wi‑Fi、蜂窝和共享网络均断开后保留蓝牙连接；不要连接任何提供网络的蓝牙共享设备。没有键鼠也应能用触摸按钮完成基础测试。
7. 开始录屏或拍下断网设置。回到主屏幕，点击固定版本图标，等待离线准备页出现并自动检查；必要时点“检查已存资源”。
8. 资源检查通过后打开工作台，再点“校验本地资源”。若页面打不开、资源缺失或一直不能校验，记录为“离线关闭重开失败”，不要恢复联网后仍记作通过。

从这里开始保持断网，完成第 4—7 节基础测试。所有“通过”都填写实际观察，不用本手册的预期代替结果。

## 4. C++ 基础必测：新源码、断点、三种单步和变量

### 4.1 粘贴一份此前没有编译过的代码

1. 语言选择 **C++17**。
2. 点“题站源码”，全选并替换为下面代码；“测试驱动”保持空白。
3. 把第一行注释的 `A` 改成你此刻随手写的独特标记，例如 `IPAD-1026-2037`，形成断网后新输入的源码。注释放在同一行，保留其余空行，以便后面的行号对应。
4. “样例输入”填 `7`，可在后面回车。输入在运行前一次性提供；当前不支持程序运行中继续输入。

```cpp
#include <cstdio> // IPAD-NEW-SOURCE-A
#include <vector>
#include <string>

int add(int left, int right) {
    int answer = left + right;
    return answer;
}

int main() {
    int n = 3;
    std::scanf("%d", &n);
    std::vector<int> values = {1, 2, 3};
    std::string label = "sum";
    int array[3] = {4, 5, 6};
    int total = add(n, values[0]);
    for (int i = 0; i < 3; ++i) {
        total += array[i];
    }
    std::printf("%s=%d\n", label.c_str(), total);
    return 0;
}
```

先点 **“编译运行”**。记录从点击到输出的时间。预期输出是 `sum=23`，正常结束、返回值 `0`；它来自 `7 + 1 + 4 + 5 + 6`。空输出、只有“成功”字样或预填示例文本均不能代替实际输出。

然后在**仍然断网**的情况下，把第 15 行数组里的第一个 `4` 改成 `9`，重新点“编译运行”。预期输出变为 **`sum=28`**。这一步确认编辑后的新代码真的参与了编译。再改回 `4`，用于下一步的固定预期。

### 4.2 设置断点，停在函数调用前

1. 点击第 **16 行**左侧行号设置断点；也可把光标放在 `int total = add(n, values[0]);` 这一行，点“在当前行切换断点”。检查“断点与编译诊断”里的请求行和实际绑定行。
2. 点 **“编译调试”**。调试器会先在程序入口暂停；此时初始化尚未执行的变量不可读是正常情况。
3. 点 **“继续”**，等到第 16 行暂停，核对真实暂停位置和断点标识。
4. 查看“局部变量”，必要时展开数组或容器：`n=7`、`values=[1,2,3]`、`label="sum"`、`array=[4,5,6]`。
5. 这时 `total` 尚在初始化前，**不应当显示已完成的值 `8`**；可以显示不可用及原因。尚未执行的语句不会因为高亮到该行就自动完成。

窄窗口中看不到面板时，点 **“调试与输入输出”**；返回源码点“代码”。不要把面板没显示误判为调试器没有变量。

### 4.3 单步进入、检查调用者，再跳出

按顺序操作，每次等界面完成暂停再点下一次：

| 操作与位置 | 应观察到的结果 |
|---|---|
| 第 16 行点“进入” | 进入 `add` 的用户源码，调用栈包含 `add` 和 `main`；参数 `left=7`、`right=1` |
| 停在第 6 行初始化前 | `answer` 尚未完成初始化，不应当预先读作 `8` |
| 点一次“跳过”，到第 7 行 `return answer;` | `answer=8` |
| 点击调用栈里的 `main` | 查看调用者这一帧的 `n=7`；`total` 仍在调用初始化期间，未完成前不可读 |
| 重新选择栈顶 `add`，点“跳出” | 返回 `main` 的调用位置；返回后赋值尚未完成的暂停点，`total` 仍可能不可读 |
| 在返回后的第 16 行再点“跳过”，到第 17 行 | 写入已完成，`total=8` |
| 监视框输入 `total`，点“查看” | 显示当前选中帧中的 `8` |
| 点“继续” | 程序最终实际输出 `sum=23`，正常结束 |

行位置与表不同、进入了错误函数、完成初始化仍不可读，或初始化前显示旧值，都保留截图并回报。不要为凑表格预期连续乱点；记录最后一次操作和当前位置即可。

### 4.4 独立检查“跳过函数调用”

重新点“编译调试”，入口暂停后“继续”到第 16 行。这次点 **“跳过”**，预期留在 `main`，走到第 17 行，且 `total=8`；不需要进入 `add`。随后“继续”到正常退出。

再重新调试，在任意暂停位置保持页面前台等待至少 40 秒，然后单步或继续，记录能否正常恢复。等待时不要切 App、回主屏或锁屏；当前普通执行预算与后台终止行为是不同情况。

## 5. C 与停止恢复：两项基础必测

### 5.1 C11 的输入输出

先导出想保留的 C++ 草稿。选择 **C11**，清空测试驱动，把题站源码换成：

```c
#include <stdio.h>
int main(void) {
    int value = 0;
    scanf("%d", &value);
    printf("ipad-c=%d\n", value * 2);
    return 0;
}
```

样例输入填 `21`。点“编译运行”，预期 **`ipad-c=42`**、返回 `0`。再在 `printf` 行设断点，编译调试，入口暂停后继续；读取 `value=21`，单步到结束。记录实际输出和暂停结果。

### 5.2 停止死循环，并立即运行下一份源码

保持 C11，把源码换成下面内容，驱动清空、输入清空：

```c
int main(void) {
    volatile unsigned int count = 0;
    while (1) {
        ++count;
    }
}
```

1. 点“编译运行”，等待状态显示正在运行。
2. 在普通运行时限到达前点击 **“停止”**。记录是否出现停止终态、界面能否继续操作；不能只以按钮变灰判断计算已经终止。
3. 马上把源码换成下面内容，再编译运行：

```c
#include <stdio.h>
int main(void) {
    puts("ipad-restart=43");
    return 0;
}
```

预期 **`ipad-restart=43`**、返回 `0`，不混入旧程序输出或旧暂停数据。若页面卡住、停止无响应或新程序不能运行，记录失败，不清除网站数据。

## 6. 刷题代码、测试驱动、诊断和复制

当前驱动由你手写，不会自动猜出题目的输入格式。只有 `Solution` 或函数的代码，把题站要求的部分放“题站源码”，本地 `main` 放“测试驱动”。

选择 C++17，“题站源码”放：

```cpp
class Solution {
public:
    int twice(int value) { return value * 2; }
};
```

“测试驱动”放：

```cpp
#include <cstdio>
#include "user.inc"

int main() {
    Solution solution;
    std::printf("%d\n", solution.twice(21));
    return 0;
}
```

1. 编译运行，预期 `42`。把驱动里的 `21` 改成 `22` 再编译，预期 `44`，确认驱动修改生效。
2. 临时删掉驱动中 `return 0;` 的分号，编译应失败，并出现指向 `driver.cpp` 的真实诊断；点击诊断应跳到驱动相应位置。补回分号后重新编译应成功。
3. 再在题站源码中制造一个明显语法错误，确认诊断指向 `user.inc`；修复后重编译。不要期待所有 C++ 错误都有中文提示，核对的是文件、行列和真实失败。
4. 点 **“复制题站源码”**，在另一个本地编辑区或你的刷题 App 粘贴，检查只包含 `Solution`，不夹带 `main`、驱动或调试文本。若网站无直接剪贴板权限，界面会给手动复制框；选中内容后用系统“复制”或键盘复制。
5. 从刷题 App 复制一段代码回来，使用“粘贴代码”或在源码框内系统粘贴；检查中文注释、换行和缩进。临时编辑自己的备份，不要误覆盖或提交正在做的题。

**当前版本在页面隐藏时会终止调试会话，原因可能显示为 `background`。** 切去刷题 App、回主屏、锁屏或离开页面后，返回时应重新“编译运行/编译调试”，不能继续依赖原暂停、旧栈帧或变量。草稿是否及时保存仍要看保存提示及下一节结果；后台行为也需要如实记录。

如果调试暂停时修改代码，旧会话仍对应旧的只读调试快照。修改稿需要重新编译。使用“查看调试快照”区分两者；不应让旧变量或高亮位置冒充新源码的执行结果。

## 7. 草稿、完整导出、关闭重开和导入

1. 在源码加入独特的中文注释，例如 `// 平板草稿恢复测试 1026-A`；保留第 6 节驱动，并在输入框写 `draft-input-1026`。
2. 等“草稿已保存 · 版本 …”出现，截图记录。若显示“修改待保存”“正在保存”或错误，不立刻关闭。
3. 导出下拉框选择 **“完整草稿”**，再点“导出”。用系统下载/保存界面把 JSON 文件留在“文件 → 我的 iPad → 算法工作台测试”。确认文件确实存在；单独导出 C/C++ 源码不包含完整驱动、语言和输入。
4. 关闭工作台后仍在断网状态，从同一个主屏固定版本入口重开。进入工作台，检查源码注释、驱动、语言和输入均恢复，不能只看页面能打开。
5. 再导出当前内容作为保险，然后对当前源码做一个临时改动。点击 **“导入”**，选择刚导出的完整草稿 JSON，核对原源码、驱动、语言和输入恢复；等保存完成。
6. 最后选择 **“仅题站源码”** 导出一次，确认文件中不带测试驱动。再将完整草稿备份留在本机，必要时联网后另备份到你选择的位置。

若出现保存失败或多窗口版本冲突，**先保留当前窗口**，用“导出当前未保存内容”保住编辑，再考虑“重试保存”或“将当前编辑存为恢复副本”。恢复副本的地址可能带草稿标识，应记录该地址；不能用关闭窗口、清缓存、清除网站数据来处理保存错误。不要在没有备份时用导入覆盖重要编辑。

## 8. 扩展测试：基础通过后继续做

这些项目独立记录，不用基础用例的通过代替它们。某项不支持或不能完成就写“失败/待验证”和提示。

- **指针**：回到第 4 节 C++ 代码，在数组声明后新增 `int *pointer = &array[1];`，在它之后的可执行行暂停。查看 `pointer` 地址及有效解引用，预期 `*pointer=5`；基础监视可尝试 `array[1]`、`pointer`、`*pointer`，拒绝时记录具体原因。插入行后按语句重新找断点，不再沿用第 16 行。
- **容器边界**：分别用空、短、长 `std::string`，空和扩容后的 `std::vector<int>`，在初始化和修改完成后暂停、展开检查真实内容。不要把空容器正常没有元素与“变量不可用”混为一谈。
- **递归栈**：用自己的小型递归函数，在递归内部暂停；逐帧点击调用者，记录每一帧的参数，不应所有帧都显示栈顶值。
- **空白行断点**：在空白行请求断点，查看实际绑定行或拒绝原因；若重定位，应能看到实际位置。
- **变量遮蔽与重复初始化**：交给 5 号提供的独立样例验证。检查内层同名变量优先、离开作用域后外层恢复，循环新一轮初始化完成前不显示上一轮旧值。
- **键鼠与触摸**：测试点击行号、选中文字、缩进、取消缩进、查找、中文输入；硬件键盘 F 键若被系统占用，使用页面按钮完成同一操作。记录横竖屏、分屏/窄窗是否遮挡按钮。
- **后台与恢复**：先导出草稿再切换 App、锁屏后返回。记录会话终止与草稿保留情况，重新编译测试。不要把“未恢复原暂停”自动填为故障，当前预期是后台终止；页面卡死、数据丢失或旧暂停冒充新会话才需另报。
- **实际成本**：分别记录第一次与第二次编译耗时、是否异常发热、页面是否被系统重载。看不到内存数值就写“未采集”，不要用约 61 MB 下载量填写内存。

## 9. 遇到问题时怎么处理

| 现象 | 你先做的事 |
|---|---|
| 地址打不开或证书警告 | 记录完整地址与提示，回报 1 号；未拿到实际可信 HTTPS 入口时先停在准备阶段 |
| “准备离线资源”失败、超时 | 保持页面前台，截图错误与版本；确认首次准备确有网络和可用空间，可重试一次，不清草稿 |
| 断网后入口打不开 / 资源缺失 | 记录为离线关闭重开失败；保留断网状态和错误证据，再单独记录恢复联网后的修复过程 |
| “打开工作台”不能点 | 回看资源校验结果；不能把灰色按钮当成准备完成 |
| 编译失败 | 检查语言、驱动是否该清空、头文件和分号；记录诊断。当前不支持 `bits/stdc++.h`，使用明确标准头文件 |
| 单步停错行、变量错误或不一致 | 停在原位置截图源码高亮、调用栈、变量和最后一次按钮；不要连续点击掩盖现场 |
| 切 App 后会话结束 | 当前会终止后台会话；回前台重新编译，另检查草稿是否保存 |
| 保存失败或冲突 | 先导出未保存内容，再按恢复按钮操作；不关闭现场，不清除网站数据 |
| 页面被系统重载、白屏或死循环停不住 | 记录当时源码、输入、已运行多久、是否切后台；有备份后可重开，分别记录停止失败与重开恢复结果 |

当前范围不包括运行中追加交互输入、任意复杂监视表达式、完整 C++ 标准库/异常/线程等。监视表达式中的函数调用、赋值、自增等可能明确拒绝；不要据此改用远程编译器替代本次测试。

v0.4.4已合入3号监视语义修复，等待5号独立复验：`010`、`00010` 应为8，`077`应为63；`08`/`09`明确拒绝。两个指针相加应拒绝；监视中的指针相减因无法证明属于同一数组而明确不支持，需要距离时写进源码重新编译后读取。有效指针加减整数仍按元素大小移动；浮点一元正负保留原类型。这些是限定支持范围，遇到拒绝应保留原因，不能把拒绝冒充计算成功。

v0.4.3已合入4号资源准备锁定与迟到导入隔离修复，并接入浅色工作台；5号已对66db2bb的已测桌面范围独立确认REV-004/005关闭，此结果不扩张为本次完整缓存包或iPad通过。校验期间运行、调试和再次校验应保持禁用，失败后只能重试校验。导入读取期间若你继续编辑，应保留新编辑并提示重新选文件，旧文件的迟到结果不应覆盖新稿。重要草稿仍请先导出备份；真实iPad文件选择与保存行为按实际观察记录。

新版入口在启动清单或脚本损坏时应显示“本版本离线入口需要恢复”。先保留错误证据，关闭本版本其他工作台窗口，恢复联网后点“联网重新准备资源”。该操作重新下载并校验完整资源，保留草稿和其他版本；断网时出现恢复页不代表已恢复离线能力。
