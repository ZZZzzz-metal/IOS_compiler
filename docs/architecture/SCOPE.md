# 需求与边界

日期：2026-10-24。首次安装、准备完整资源和主动更新可以联网；日常使用期间只依靠 iPad，本机编译新 C/C++ 源码，执行并进行真实源码调试。iPad 型号、iPadOS、可用空间、签名账号和开发设备条件未知，不能据此承诺性能或安装方式。

## 必须实现

工作流为复制源码 → 粘贴/编辑 → 提供 stdin → 编译 → 运行或断点调试 → 排错修改 → 复制回题站。首轮仅支持一个带 main 的 C/C++ 翻译单元，C11/C++17 为验证目标。

首版核心：真实编译运行、标准输入输出、编译错误定位、源码断点、继续、单步进入/跳过/跳出、局部变量、调用栈和停止。标量、数组、指针及 string/vector 内容分别验证，基础监视表达式支持范围单列。本地草稿、复制粘贴、导出同属首版。具体实现状态统一读取 contracts/capabilities.json。

不扩展题库、账号、云后端、远程电脑依赖、复杂工程构建、Windows GUI 程序或插件市场。没有自动适配全部题站/函数签名、任意表达式求值或与 OJ 性能等价的承诺。bits/stdc++.h 作为额外扩展单独验证。

## 仅函数 / Solution 类的驱动设计

编辑区保留“题站源码”和“测试驱动”两个可编辑内容。首个关卡仍用完整 main 程序；后续驱动不自动猜测签名或参数类型。

建议文件组织：user.inc 保存题站源码；driver.cpp 显式 include user.inc 并定义 main。把两者和 driver.cpp 作为 translationUnit 一同纳入 SourceSnapshot。include 路径由虚拟文件系统解析，因此编译诊断和断点可直接保留各自文件身份。若候选必须拼接，生成单元也纳入快照，输出逐段 sourceMappings，覆盖中文与驱动行号。

用户可自行编辑 include、对象初始化、调用和输入解析。例如驱动包含 `<iostream>`，include 用户文件，在 main 内创建 Solution 并调用其已有函数；不给所有题目强套统一模板。选择 C 时使用 C 驱动与声明，不强迫 C++ 包装。

修改题站源码或驱动都产生新 sourceHash，当前会话继续绑定旧快照，显示需重新编译。复制回题站默认只复制 user.inc 内容；完整导出另提供源码、驱动、语言/标准、stdin 和清单。一个完整 main 文件也可以直接作为 translationUnit，无须额外驱动。

## 环境与资源限制

实际目标 ABI、字宽、标准库、异常/RTTI、文件系统、线程等由 2/3 用真实组合声明。未支持范围和性能必须随所选组合公开，不能把 Wasm32、模拟 Linux 或 iPad 原生运行的行为称为在线判题环境。

设定可中断的运行预算、内存/输出量限制及变量分页。调试人工暂停不消耗普通运行墙钟预算；后台行为按平台验证后声明。停止死循环后仍能操作编辑器并再次调试是必过项。
