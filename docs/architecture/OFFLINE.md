# 离线资源、完整性与升级

首次安装/主动更新可联网；日常冷启动、编辑新程序、编译、运行、真实调试、保存与导出全部本地完成，这是产品目标。2026-10-26新增 [完整Web缓存实验](../../app/offline/README.md)，桌面关闭静态服务器后重开及新源码编译调试已有实测，详见 [交付报告](OFFLINE-INTEGRATION-2026-10-26.md)。本文其余条目仍是完整产品约定；正式清单未激活、真机未验，不将实验事务等同于产品全部升级与回退实现。

## 完整组合

contracts/offline-bundle.json 声明同一 bundleId、协议版本、compatibilityId，以及界面、编译器、链接器、sysroot、标准库、运行时、调试器的全部资源。字体、编辑器 worker、符号解析器、STL 格式化器和许可文件也必须本地打包，不得留 CDN 隐式依赖。

每个资源记录相对路径、固定来源/版本、SHA-256、字节数、角色与本地许可文件；一个文件可覆盖多个角色。兼容组合必须与 contracts/compatibility-profiles.json 的精确组件版本/目标/ABI/格式一致。profile 的 resourceManifestHash 绑定完整资源清单与字节哈希；不能只复制 compatibilityId 并自报不同资源即通过。资源文件存在不等于通过校验。

当前清单为空、status=unprepared、compatibilityId=null。界面只能表示“尚未准备完成”。开发参考检查 verifyOfflineBundle 会验证本地资源字节、角色、许可文件是否也纳入校验；它不证明该资源真的有宣称的执行能力，也不代替 iPad 离线关卡。

## 激活事务

流程为 unprepared → staging → 字节与组合验证 → 真实自检 → active。只有完整清单全部通过、可用空间足够并且离线资源自检成功后，才原子切换 active 指针。下载中断、校验失败、版本冲突继续使用上一完整 active 组合，不混用新编译器与旧运行时。更新只能由用户主动触发，不在离线编译过程中偷偷下载。

旧调试会话锁定启动时的组合，更新待会话停止后切换；或明确提示停止后重新编译。旧产物不得未经兼容验证由新运行时直接载入。保留上一个完整组合以便回退，清理旧资源前确认无会话/构建引用。

离线就绪必须每次启动重新检查激活清单及资源可访问性；发现资源被回收、损坏或存储写入失败即撤销就绪状态。可缓存校验结果但不能用缓存状态掩盖丢失资源。PWA 若被选中，需另外验证 service worker 版本切换、缓存清理与持久化申请；浏览器存储不能保证永不回收，参见路线证据。

## 草稿保护

草稿数据库与工具链资源分开。更新前保留草稿可导出副本，迁移采用复制写入、新版本校验与原子切换，不先清空旧库。失败可回退，保存失败明确反馈。提供用户源码导出和完整项目导出，实际复测重开恢复、中文/换行和驱动内容。

原生应用的资源与签名安装更新也须匹配，不把“资源包可用”误写为“应用可永久启动”。安装渠道、有效期和首次联网条件见 ROUTES.md，最终按所选分发方式实测说明。
