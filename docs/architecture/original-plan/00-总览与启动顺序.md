# iPad 离线 C/C++ 编译调试工具：多上下文执行方案
日期：2026-10-23。此文档是开发分工，不是完成产品或可行性验证的声明。

## 项目目标
从刷题软件复制代码 → 粘贴到本工具 → 完全离线编译运行 → 断点/单步/变量/调用栈调试 → 复制修改后的代码回去。用户希望获得类似 Visual Studio 的核心编译调试体验，轻量指范围小，不代表可以删掉调试器。

## 分工
| 上下文 | 唯一主要职责 | 逻辑所有权 |
|---|---|---|
| 1 总架构与集成 | 确定路线、共享接口、共同骨架、合并和可安装交付 | contracts/、根配置、启动入口、docs/architecture/ |
| 2 离线编译工具链 | 编译器、头文件/标准库、真实产物、调试信息、编译诊断 | compiler/、其工具链资源 |
| 3 运行与源码级调试 | 执行、输入输出、断点、单步、变量、栈、停止 | debugger/、其运行资源 |
| 4 iPad 编辑器与调试界面 | 编辑、键鼠、调试面板、代码传入传出、基础本地保存 | ui/、storage/ |
| 5 独立测试与验收 | 实际离线及调试验收、复现样例、兼容性记录 | tests/、fixtures/、docs/validation/ |

## 怎么开上下文
1. 先开“总架构与集成”，把 01 文件全文作为初始任务。它先交付仓库位置、基础结构、接口草案和协作规则，不等待完整产品完成。
2. 再开“离线编译工具链”“运行与源码级调试”“独立测试与验收”，分别贴入 02、03、05 文件，同时提供步骤 1 的仓库位置和共同基线。
3. 上下文 2 和 3 联合做最小可运行原型：在真实 iPad 上完成断网后新源码编译、断点命中、单步、变量和调用栈查看。这一关不能用桌面测试或仅运行 Hello World 替代。
4. 关卡通过后，上下文 1 冻结技术路线和接口，再让“iPad 编辑器与调试界面”读取 04 文件开始正式实现；此前可以先做交互草图。
5. 各模块阶段性交付给上下文 1 逐一集成，上下文 5 独立复测。必要时由用户把交付记录转发到集成上下文；不假设不同聊天天然共享全部历史。
6. 第一轮交付先跑通一条完整调试流程，再处理边角功能。若核心关卡失败，优先修正运行/调试路线，不得自动改为远程方案或取消调试。

## 必须通过的最小验收
安装准备完成后，关闭应用、断网，再重新打开。粘贴一份此前没有编译过的 C++ 程序，包含循环、函数调用、数组和 vector。
- 编译成功，输入样例，正确运行输出。
- 在源代码行设置断点，显示实际绑定位置。
- 断点暂停后，局部变量和数组/vector 的可见内容符合实际。
- 单步进入函数、单步跳过调用、单步跳出函数；查看并切换调用栈。
- 修改代码后必须重新编译，调试会话准确对应新源码。
- 停止死循环后，界面可用，下一次编译和调试能正常进行。
- 另以普通 C 程序验证编译、输入输出和基础调试。
- 重启应用后恢复本地草稿；复制/导出仍可用。
- 记录具体设备、iPadOS、应用版本、安装形态、实际结果与未验证项。

## 关键接口约定
由上下文 1 与 2、3 联合确定：
- 编译请求：源码快照、语言/标准、编译模式和请求编号。
- 编译结果：buildId、sourceHash、工具链版本、目标环境、产物和调试信息引用、源码映射、diagnostics。
- 调试会话：sessionId、buildId、状态、事件序号和暂停编号。
- 调试命令：启动、设置断点、继续、暂停（若支持）、stepInto、stepOver、stepOut、停止。
- 查询：调用栈、当前栈帧的作用域/变量；基础监视表达式按明确能力集开放。
- 事件：状态变化、断点绑定结果、暂停位置和原因、stdout/stderr、退出/错误。
- 输入首版以运行前提供完整 stdin 为主；交互输入是否支持明确标识。
- 行列编号、字符编码和源路径归一化统一；旧会话和旧暂停时刻的查询结果不得覆盖当前状态。
- 用户调试暂停期间不应按普通运行墙钟时间自动超时；运行时间限制与调试控制分开定义。
- 变量查不到必须显示原因，不能虚构结果；不可执行行的断点必须告知实际绑定行。

## 选型证据与待验证事项
- [Clang/LLD in WebAssembly](https://github.com/binji/wasm-clang)：说明将编译器、链接器和 C++ 库放入浏览器的已有思路；原仓库自称实验性 demo，不能据此承诺 iPad 成品兼容性。
- [Emscripten 调试文档](https://emscripten.org/docs/porting/Debugging.html)：区分 DWARF 和源码映射。文档的浏览器调试路径不等于我们的 iPad 应用内调试已实现。
- [LLDB WebAssembly 调试文档](https://lldb.llvm.org/resources/wasm-testing.html)：说明运行时和调试器的协作方案；必须另行验证能否在目标 iPad 应用形态中本地部署，不能依赖外置电脑调试器。
- [WebKit 存储政策](https://webkit.org/blog/14403/updates-to-storage-policy/)：若选择网页路线，应处理持久化、完整离线资源与本地代码导出；不能把浏览器缓存当永久保存承诺。
这些都是候选路线的依据，尚未对用户设备做实际测试。原生路线需要的构建、签名和安装条件由上下文 1 查证并说明，不预先假设已具备。
