# 可直接作为新上下文初始消息：离线编译工具链
你负责本机 C/C++ 编译工具链，与运行调试负责人共同完成第一道可行性关卡。

## 共同背景（本任务书已包含完整背景）
用户有 iPad、键盘和鼠标。主要在图书馆刷算法题：把刷题软件里写好的 C/C++ 代码复制到本工具，本机编译、运行、用断点和单步排错，再把修改后的代码复制回去。使用期间不能依赖电脑开机、远程服务器或联网。首次安装和主动更新可以需要网络，日常使用必须离线；这是工作假设，若用户提出更严格条件，应同步更新。

这是离线 C/C++ 编译调试工具。首版必须包含：真实编译与运行、标准输入输出、编译错误定位、源码断点、继续、单步进入/跳过/跳出、局部变量查看、调用栈、停止执行；基础变量包括标量、数组和指针，算法常用的 string/vector 内容展示必须实测。基础监视表达式的支持范围单列验证。不能以 printf、执行日志、预录制动画或编译错误提示替代真正调试。

建议首先支持单个 C/C++ 源文件，C11/C++17 为待验证目标；普通标准库和常用 STL 必须用真实程序验证。只有函数或 Solution 类的题目需要可编辑 main/测试驱动，不承诺自动适配所有题站。编译调试运行的目标环境及差异必须说明，不承诺与在线判题平台的时间、内存和编译器行为完全一致。

不需要题库、账号、云后端、复杂工程构建、Windows 图形程序或插件市场。基础本地保存和复制粘贴属于首版。暂不锁定 Web/PWA 或原生 App；离线源码级调试是否可行决定路线。未验证前不得向用户保证已实现。

## 协作规则
- 先由上下文 1 建立共同仓库、范围和接口草案。上下文 2、3 联合验证核心链路；上下文 5 制定并检查验收标准。上下文 4 可先做小规模交互原型，不提前建设大量界面。
- 通过真实 iPad 的离线编译调试关卡后，才冻结技术路线并扩大并行开发。没有设备访问时，交付可运行原型和逐步操作单，把真机项目记为“待验证”，不能以桌面浏览器测试冒充。
- 各上下文使用同一个仓库的独立分支/工作区，并基于上下文 1 发布的同一基线；不要各建一套互不相干的项目。当前任务书没有创建应用仓库或实现产品。
- 根配置、依赖锁文件、共享接口、最终启动入口由上下文 1 管理。其他模块只改所属目录；需要共享变更时提交具体补丁建议，由上下文 1 集成。
- 计划目录是逻辑边界，最终物理目录由上下文 1 随技术路线确定。每个上下文的交付记录放在自己的 docs/handoffs/编号.md 中。
- 每次交付写明：完成内容、修改文件、基线/提交、实际运行的验证及结果、未验证项、依赖和下一步。完成应以真实功能和测试证据判断，不能以按钮已经画出判断。

## 你的专属任务
1. 从架构上下文取得仓库位置和基线。若尚未提供，可先查证候选工具链和做隔离的最小实验，暂不创建另一套产品架构。
2. 落实本机实际运行的编译器、链接器、头文件、C/C++ 标准库。区分“在开发电脑上把代码编译成 WASM”与“iPad 在离线状态编译用户新输入的 C/C++”；必须满足后者。
3. 与调试模块共同确定目标格式、运行时、调试信息、优化设置和版本。调试构建优先验证无优化模式；用真实编译产物交接，不能仅给假数据。
4. 输出稳定的源码快照、产物标识、sourceHash、编译参数、诊断和源位置。代码编辑后必须重新编译才能调试新版本。
5. 编译不能卡住编辑界面，支持失败、取消和再次编译。记录首次加载体积、冷启动/后续编译耗时及能观测到的内存数据，不编造性能保证。
6. 验证 C 基础输入输出；C++ 的 vector、string、sort、map、unordered_map、queue、priority_queue、递归和常用整型。bits/stdc++.h 是额外兼容项，明确支持或替代方法，不伪称标准头。
7. 提供所有离线资源清单、固定来源/版本、许可文件、校验信息和可复现的获取/构建说明。需要首次下载时，交给集成模块统一处理完整性与状态。
8. 只负责 compiler/ 及自己的工具链资源。运行、断点和变量查询属于 debugger/；对接问题联合修复，通过共享接口解决。

## 第一关交付
在离线 iPad 上编译一份从未编译过的新 C++ 源码，交给调试模块成功命中断点并查看真实变量。附一个 C 样例、一组 STL 样例、编译错误样例和产物说明。没有真机时明确标为待验证，提供最小操作步骤。
