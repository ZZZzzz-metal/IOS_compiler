# 模块目录与所有权

| 负责人 | 目录 | 交接对象 |
|---|---|---|
| 1 总架构与集成 | 根配置/锁文件、app/、scripts/、contracts/、docs/architecture/ | 同一版本的入口、接口、能力与资源组合 |
| 2 离线编译 | compiler/（含专属资源） | CompilerAdapter、真实构建、版本与许可清单 |
| 3 执行调试 | debugger/（含专属资源） | DebuggerAdapter、真实会话与查询 |
| 4 界面与保存 | ui/、storage/ | 界面消费者、StorageAdapter、传入传出 |
| 5 独立验收 | tests/、fixtures/、docs/validation/ | 真实样例、预期、结果、设备证据 |
| 每位负责人 | docs/handoffs/自己的编号.md | 本轮变更、验证、依赖和下一步 |

共同骨架由 1 号首次建立；之后目录按表分工。物理目录先保持平台中立；选型后由 1 号统一调整并提供迁移映射，不能各建一套根应用。根 package.json 只用于当前开发检查，不表示最终 iPad 运行环境。

共享改动提交具体补丁建议（问题、涉及文件、兼容影响、验证方法），由 1 号整合契约与根依赖。依赖必须固定版本、保留锁文件及必要资源许可。其他模块不自行更新根锁文件。

各模块在独立工作区/分支开发，依次集成。1 号先校验身份/版本和交付记录，再运行相关真链路；5 号独立复测。冲突由相关所有者解释，1 号整合，不用覆盖文件方式抹掉他人工作。
