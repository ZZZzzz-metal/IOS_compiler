## 新缺陷VAL-004：旧调试快照隐藏仍生效的断点

归属4号UI，建议P2。本标签可稳定复现，影响旧快照断点列表和行号标记；源码与运行快照隔离仍有效。首次在新递归程序观察到，2026-10-26又用 [七行最小源码](../../fixtures/regressions/ui-stale-breakpoints.cpp)独立确认。

复现步骤：

1. C++17、空driver与stdin，粘贴最小源码；第4行设断点，编译调试，从入口继续到4行，i=0。面板明确显示“main.cpp:4:1 · 已绑定”。
2. 暂停时在编辑稿末尾加一行注释，再点击第4行移除编辑稿断点。不要重编译。
3. 点击“查看调试快照”，显示原始只读七行源码，却提示“尚未设置断点”，行号断点标记也消失。
4. 点击继续，仍在原main.cpp:4:1暂停，i=1。旧会话继续使用原断点是快照隔离的合理行为；错误是旧快照的显示集合来自编辑稿。

预期：旧快照应显示该会话的原绑定与请求/实际位置；编辑稿断点变更明确用于下次编译。不能通过自动删除旧会话断点掩盖显示错误。

根因已交叉审阅：`ui/src/main.mjs:57`行号标记、`:80`列表遍历、`:87`空提示均读取全局编辑稿`requested`；`:217-219`在源码已变后只改编辑稿，不对旧会话发送setBreakpoints。权威会话绑定仍保存在`session-controller.mjs:92`的`view.breakpoints`。建议只读旧快照统一用该会话的绑定集合渲染列表、标记及空提示，保留隔离条件。详细建议见 `review/val-004-static-analysis.md`，5号未修产品。

证据：[最小失败JSON](../../tests/evidence/integrated-person05-v0.3.0-2026-10-25/browser/val004-minimal-results.json)、[实际截图](../../tests/evidence/integrated-person05-v0.3.0-2026-10-25/browser/val004-minimal.png)。
