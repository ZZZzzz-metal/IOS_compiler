	2 text # 键盘快捷键速查

先打开工作台并完成“校验本地资源”，再开始编译运行或调试。展开页面上的“键盘快捷键”可查看对照表和切换方案；快捷键与对应按钮使用同一套可用状态。

默认是“无 F 键：Control＋数字行”。选择“仅标准 F 键”后关闭数字行替代组合，标准 F 键在两种方案中都有效。选择按当前浏览器来源保存；换浏览器、协议、主机或端口不会共用设置。浏览器拒绝保存设置时，本次选择仍有效，下次打开会读取此前成功保存的选择，或使用默认方案。

## 七个操作

| 操作 | 标准 F 键 | 默认数字行方案额外提供 | 可用时的行为 |
|---|---|---|---|
| 开始 / 继续 | F5 | Ctrl+5 | 无活动会话时编译调试并在入口暂停；已暂停时继续 |
| 编译运行 | Ctrl+F5 | Ctrl+6 | 无活动会话时编译并直接运行 |
| 停止 / 取消编译 | Shift+F5 | Ctrl+Shift+5 | 停止当前会话，或请求取消正在进行的编译 |
| 当前行断点 | F9 | Ctrl+9 | 在源码光标所在行切换断点 |
| 单步跳过 | F10 | Ctrl+0 | 已暂停时执行下一步，跳过函数内部 |
| 单步进入 | F11 | Ctrl+- | 已暂停时尝试进入函数 |
| 单步跳出 | Shift+F11 | Ctrl+Shift+- | 已暂停时执行到当前函数返回 |

Ctrl 指键盘上的 **Control**，不是 Command（⌘）。数字使用字母上方的数字行，`0` 在 `9` 右侧，减号 `-` 在数字 `0` 右侧；小键盘数字不作为这些替代键。数字行方案按物理键位识别，按住 Shift 后显示 `%` 或 `_` 也不改变对应组合。此方案不需要 Fn，也不用 Option；标准方案则需要键盘与系统实际发送 F 键事件。

只有表格中完整列出的组合才会触发调试动作；额外修饰键造成的未列出组合不会触发。Command、Option／Alt 和 AltGraph 均不参与这些调试快捷键。不要使用 VoiceOver 的 Control+Option 组合作为本工具快捷键。

标准键参考 [Microsoft Visual Studio 官方快捷键表](https://learn.microsoft.com/en-us/visualstudio/ide/default-keyboard-shortcuts-in-visual-studio?view=vs-2022)。本工具的 F10 仅在暂停时跳过，不提供 Visual Studio 的首次按 F10 启动调试；也未提供重启（Ctrl+Shift+F5）或运行至光标（Ctrl+F10）。数字行组合是本工具的补充方案。

## 焦点与状态

- F9／Ctrl+9 前先点击源码，把光标放在目标行。焦点在其他位置时不切换断点。
- 输入样例、查找、监视、其他输入框或下拉框有焦点时，以及弹窗打开或中文组合输入期间，不触发调试快捷键。离开输入框后可点回源码再操作。
- 查看“调试快照”时源码和断点只读；返回编辑稿后才能改稿或切换断点。继续、停止和单步仍按当前真实会话状态决定是否可用。
- 运行中、等待上一条继续／单步命令确认、状态待同步等阶段，不可用的单步不会执行。等状态更新后再按下一次。
- 长按不会反复触发调试动作。在可处理快捷键的焦点范围内，页面会阻止当前方案中精确识别的组合键的浏览器默认行为，即使对应动作暂不可用；未识别的组合不受这条规则保护。

iPad、浏览器或辅助功能可能在事件到达页面前截获组合键。没有响应时使用对应按钮，并记录设备和按键；这里不保证某款键盘上的组合能够到达页面。

## iPad 实机确认小操作单

以下是待执行的确认步骤，不是已通过的真机结果。使用提供给平板的实际版本入口；开发电脑上的 `127.0.0.1` 地址不是 iPad 入口。

1. 记录 iPad 型号、iPadOS、键盘型号与布局、浏览器／主屏入口、页面版本和地址。选择默认数字行方案，完成资源校验。先用按钮确认能够启动、暂停和停止，便于区分运行问题与按键未到达。
2. 导出重要草稿，选择 C++17，清空测试驱动与样例输入，再在题站源码中放入下列程序。

   ```cpp
   #include <cstdio>
   int bump(int x) {
       int y = x + 1;
       return y;
   }
   int main() {
       int n = 4;
       int result = bump(n);
       std::printf("%d\n", result);
       return 0;
   }
   ```

3. 点击 `int result = bump(n);` 所在行，按 Ctrl+9，确认出现断点请求；再次按应取消，再按一次重新设置。按 Ctrl+5，等入口暂停；再按 Ctrl+5，核对是否停在该调用附近，并查看实际绑定位置。
4. 在调用行暂停时按 Ctrl+-，查看真实执行行与调用栈是否进入 `bump`；按 Ctrl+0 查看单步变化，再按 Ctrl+Shift+- 查看返回。每次都等待状态稳定，结果以实际暂停位置为准，不能仅以按钮变色判定成功。
5. 按 Ctrl+Shift+5 停止；结束后按 Ctrl+6，核对输出 `5`。另起一次调试，长按一个单步组合，核对一次按住不会连续发出动作；等待命令确认时再按单步也不应堆积执行。
6. 分别在样例输入、查找框、监视框和打开的手动粘贴弹窗中按组合键，确认不会意外开始、停止或单步；在中文组合输入时重复确认。查看只读调试快照时按 Ctrl+9，确认不会改断点。
7. 切到“仅标准 F 键”，确认数字行替代键不再触发；若键盘能发送 F 键，再逐项确认表格中的标准键。切回默认方案，刷新或重开同一来源，核对方案是否记住；若页面提示未允许保存，记录本次可用、重开后结果即可。
8. 对每个未响应的键，记录按键、焦点、页面状态，以及是否出现系统／浏览器操作，再用按钮完成同一动作。VoiceOver 场景单独记录，勿用 Control+Option 替代本表组合。

离线冷启动、断网后关闭重开、关闭辅助电脑后编译全新源码等，还需按发布入口提供的《平板操作手册》单独确认；快捷键成功不能替代完整离线验收。

## 验证边界

受控回归用于核对组合解析、焦点与状态门禁、重复按键处理以及设置保存失败后的本次行为；模拟键盘事件不能证明物理 iPad 键盘能发送相同事件。桌面真实浏览器中的编译、断点、单步和设置操作，也只证明所记录浏览器与版本的结果。本轮具体检查结果以交付记录为准，真实 iPad 键盘、Safari／主屏入口和 VoiceOver 尚待实机确认。

键盘照片仅作本地键位参考，不加入 Git 或随文档分发，也不能作为按键事件到达的证据。新快捷键随源码交付后仍需由 1 号重新打包；已有固定版本不会自动获得更新。
